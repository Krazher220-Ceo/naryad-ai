# Экраны M1: спецификация

Экраны собираются из компонентов `@/components/ui` (см. `docs/ui/design-system.md`). Наброски сделаны под ширину 360 px. Правило для всех экранов: страница `bg-canvas`, поле 16 px, сверху `AppHeader`, главное действие лежит в `BottomActionBar`, у контента нижний отступ `pb-36`.

Обозначения в набросках: `[[ … ]]` — кнопка 56 px, `[ … ]` — вторичная кнопка 48 px, `▌` — красная полоса аварийного наряда, `●` — точка состояния исполнителя.

## 1. Панель смены мастера `/master`

**Цель.** За 3 секунды понять, что горит, кто свободен и сколько всего нарядов.

**Сверху вниз.**
1. `AppHeader`: ФИО и роль.
2. Счётчики смены: 4 плитки в сетке 2×2 («Аварийные», «Просрочено», «В работе», «Ждут принятия»). Плитки с «Аварийными» и «Просрочено» при ненулевом значении красные. Нажатие на плитку фильтрует доску.
3. «Исполнители»: горизонтальный ряд `WorkerChip`, сначала свободные, потом занятые, с очередью и не на смене.
4. «Наряды»: список `ListItem`. Порядок такой: аварийные, просроченные, остальные открытые по сроку. Закрытые и отменённые свёрнуты в конце. В строке есть `PriorityBadge`, `StatusBadge` и `OverdueTag`, справа срок.
5. `BottomActionBar`: `[[ Выдать наряд ]]`.

**Компоненты:** `AppHeader`, `Card`, `WorkerChip`, `ListItem`, `PriorityBadge`, `StatusBadge`, `OverdueTag`, `BottomActionBar`, `Button`, `EmptyState`, `ErrorState`, `Skeleton`, `InlineNotice`.

**Главное действие:** «Выдать наряд».

**Пусто.** Список нарядов пуст: `EmptyState` с текстом «Нарядов нет. Нажмите „Выдать наряд“ внизу». Исполнителей нет: `EmptyState` из `ui.empty.workers*`.
**Ошибка.** `ErrorState` с кнопкой «Повторить». Если нет сети, сверху `InlineNotice tone="offline"`, а данные остаются последними загруженными.
**Загрузка.** Три `Skeleton h-18`.

**360 px.** Одна колонка, исполнители прокручиваются по горизонтали внутри своего ряда (у страницы горизонтальной прокрутки нет).
**Ноутбук (от lg).** Две колонки: слева исполнители списком, справа доска нарядов колонками по статусам (Выдан / В работе / Приостановлен / Проверка ИИ). Аварийные и просроченные в каждой колонке стоят наверху. Кнопка «Выдать наряд» остаётся внизу по центру, шириной до 576 px.

## 2. Выдача наряда `/master/orders/new`

**Цель.** Выдать наряд за минуту и не больше чем за 6 нажатий. Ввод текста нажатием не считаем, но и он сокращается шаблонами.

**Что предзаполнено.**

| Поле | По умолчанию | Откуда |
|---|---|---|
| Участок | участок выбранного оборудования | `equipment.section_id`, отдельно не выбирается |
| Тип работ | «Внеплановые» | чаще всего; меняется одним нажатием в `SegmentedControl` |
| Приоритет | «Обычный» | одно нажатие на «Аварийный» |
| Исполнитель | первый свободный по специальности оборудования | `worker_board`: свободен → с наименьшей очередью |
| Срок | сейчас + норматив шифра (без шифра 4 ч, для аварийного 1 ч) | `fault_codes.norm_hours` |
| Описание | пусто или текст шаблона | чипы последних и типовых описаний |
| Фото «до» | по желанию | `PhotoPicker` |

**Путь мастера (6 нажатий).**
1. `[[ Выдать наряд ]]` на панели смены.
2. Выбрать оборудование: список «Недавние» из 5 последних единиц плюс поиск. Участок подставится сам.
3. Нажать чип типового описания («Течь масла», «Не запускается»…) или набрать текст.
4. Приоритет «Аварийный» одним нажатием. Это нужно, только если приоритет не «Обычный».
5. Исполнитель: показан предложенный `WorkerChip` с кнопкой «Сменить». Если подходит, нажатие не нужно.
6. `[[ Выдать ]]`.

Если все значения по умолчанию подходят, выдача занимает 4 нажатия: 1, 2, 3 и 6.

**Компоненты:** `StepForm` (шаги: Оборудование → Что сломано → Приоритет и тип → Исполнитель и срок → Фото), `Select`, `TextArea`, `SegmentedControl`, `WorkerChip`, `PhotoPicker`, `InlineNotice`, `Toast`.

**Главное действие:** «Выдать».

**Пусто.** Свободных исполнителей нет: `InlineNotice tone="warning"` с текстом «Все заняты, наряд встанет в очередь к …», а исполнитель всё равно предложен, тот, у кого очередь меньше.
**Ошибка.** Если сервер отказал, текст ошибки из `ActionResult` показывается в `InlineNotice tone="danger"`, а введённые данные не теряются. Если нет сети, наряд сохраняется в очереди отправки и показывается `Toast tone="offline"`.
**Дубль (уровень 4).** Если по оборудованию уже есть открытый наряд, показывается `InlineNotice tone="warning"` со ссылкой на этот наряд.

**360 px.** Шаги по одному, «Назад» и «Далее» внизу. На последнем шаге вместо «Далее» стоит «Выдать».
**Ноутбук.** Все шаги на одной странице, кнопка «Выдать» в конце формы.

## 3. «Мои наряды» исполнителя `/worker`

**Цель.** Сразу увидеть, что делать сейчас и что дальше.

**Сверху вниз.**
1. `AppHeader`.
2. Если есть новый наряд, ждущий принятия, наверху стоит `Card tone="emergency"` (для аварийного) или обычная `Card` с кнопками `[[ Принять ]]` и `[ В очередь ]`. Кнопка «Отклонить» стоит ниже, отдельно.
3. «Сейчас»: наряд в работе или на паузе, крупной карточкой.
4. «Очередь»: список `ListItem` по приоритету и сроку, аварийные сверху.
5. «Сделано сегодня»: свёрнутый список (исполнено, проверка ИИ, закрыто).

**Компоненты:** `Card`, `ListItem`, `PriorityBadge`, `StatusBadge`, `OverdueTag`, `Button`, `EmptyState`, `ErrorState`, `InlineNotice`.

**Главное действие:** у карточки «Сейчас» это следующий шаг по статусу (см. экран 4). Если наряда «Сейчас» нет, главное действие — «Принять» у нового наряда.

**Пусто.** `EmptyState` с текстом «Нарядов нет. Когда мастер выдаст наряд, он появится здесь, и телефон подаст сигнал.»
**Ошибка.** `ErrorState` с кнопкой «Повторить». Без сети остаётся последний список и `InlineNotice tone="offline"`.

**360 px.** Одна колонка.
**Ноутбук.** Та же колонка шириной до 640 px по центру: исполнитель с ноутбука не работает, раскладку не усложняем.

## 4. Карточка наряда исполнителя `/worker/orders/[id]`

**Цель.** Понять, что, где и к какому сроку, и сделать следующий шаг одним нажатием.

**Сверху вниз.**
1. Кнопка «‹ Назад» (48 px) и номер наряда.
2. `PriorityBadge`, `StatusBadge`, `OverdueTag`.
3. Описание (text-xl), оборудование, участок, срок, мастер.
4. Фото «до» (превью, нажатие открывает на весь экран).
5. История: события наряда (время, действие, причина).
6. `BottomActionBar` с кнопками по статусу.

**Кнопки по статусу** (переходы из `lib/orders/transitions.ts`):

| Статус | Главная `[[ ]]` | Вторичная `[ ]` | Опасная (отдельно, с листом) |
|---|---|---|---|
| `issued` | Принять в работу | Поставить в очередь | Отклонить → `ConfirmSheet` + `ReasonPicker(REJECT_REASONS)` |
| `queued` | Принять в работу | — | — |
| `accepted` | Начать исполнение | — | — |
| `in_progress` | Исполнено → экран 5 | — | Приостановить → `ConfirmSheet` + `ReasonPicker(PAUSE_REASONS)` |
| `paused` | Продолжить | — | — |
| `rework` | Начать исполнение | — | — |
| `done`, `ai_review`, `closed`, `rejected`, `cancelled` | — (панель скрыта, показан `InlineNotice` о том, что дальше) | — | — |

Опасная кнопка стоит под главной, через отступ 16 px, в варианте `ghost`/`danger` с текстом, чтобы её нельзя было нажать вместо главной.

**Компоненты:** `PriorityBadge`, `StatusBadge`, `OverdueTag`, `Card`, `BottomActionBar`, `Button`, `ConfirmSheet`, `ReasonPicker`, `InlineNotice`, `Toast`, `Skeleton`, `ErrorState`.

**Пусто.** Нет фото «до»: блок не показывается.
**Ошибка.** Наряд не найден: `ErrorState` с текстом `orders.errors.notFound`. Если переход отклонён сервером, показывается `Toast tone="danger"` с текстом из `ActionResult`, а статус не меняется. Если нет сети, действие ставится в очередь, кнопка показывает новый статус и `InlineNotice tone="offline"`.

**360 px.** Всё в колонку, панель действий внизу.
**Ноутбук.** Слева детали и фото, справа история. Кнопки внизу.

## 5. Закрытие наряда `/worker/orders/[id]/close`

**Цель.** Заполнить закрытие за 1–2 минуты в перчатках.

**Шаги `StepForm`.**
1. **Работы.** `TextArea` «Что сделано» (обязательно). Над полем чипы типовых работ по шифру.
2. **Шифр.** `Select` шифров. Подсказанный шифр стоит первым, остальные отсортированы по частоте на этом оборудовании.
3. **Материалы.** Список типовых материалов шифра, у каждого `NumberStepper` (по умолчанию 0, для типовых `typical_qty`). Ниже `[ + Добавить материал ]`.
4. **Фото «после».** `PhotoPicker`, до 5 фото. Для внеплановых работ фото обязательно: над ним `InlineNotice tone="warning"` с `orders.afterPhotoRequired`, и шаг не пропускает дальше без фото.
5. **Комментарий.** `TextArea` по желанию.
6. `[[ Отправить ]]` → наряд переходит в статус `done`, затем в `ai_review`, показывается `Toast` «Отправлено на проверку».

**Пусто.** Если у шифра нет типовых материалов, показывается `EmptyState` и кнопка «Добавить материал».
**Ошибка.** Если не загрузилось фото, у превью появляется `InlineNotice tone="danger"` с текстом `orders.errors.photoUpload` и кнопкой «Повторить», остальные данные сохраняются. Без сети закрытие встаёт в очередь отправки.

**360 px.** По одному шагу, прогресс «Шаг N из 5». «Далее» неактивна, пока шаг не заполнен.
**Ноутбук.** Все пять блоков на одной странице, кнопка «Отправить» в конце. Пока что-то не заполнено, она неактивна и рядом надпись «Заполните обязательные поля».
