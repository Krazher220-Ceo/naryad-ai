# Архитектура «НарядAI»

Документ для команды и жюри: из чего состоит система, где живёт каждое правило и почему так.

## Общая схема

```
Телефон (PWA, Android/iOS)        Ноутбук руководителя
        │                                  │
        └──────────────┬───────────────────┘
                       ▼
        apps/web — Next.js 16 на Vercel (регион fra1, рядом с базой Supabase eu-central-1, см. apps/web/vercel.json)
        ├─ экраны мастера, исполнителя, руководителя, /demo для жюри
        ├─ серверные действия (lib/orders/actions.ts)
        ├─ lib/ai — единственная точка вызова моделей
        ├─ lib/analytics — рейтинг, смена, аномалии, отчёты
        └─ /api/cron/deadlines, /api/telegram/webhook, /api/export/[report]
                       │
        ┌──────────────┼──────────────────────────┬─────────────────────┐
        ▼              ▼                          ▼                     ▼
  Supabase         DeepSeek API              services/fast-ai       Telegram Bot API
  PostgreSQL       (deepseek-flash:          (Laya, дообученная;    (уведомления)
  Auth, Storage,    текст и фото)             FastAPI на своём
  Realtime,        или Ollama локально        сервере)
  pg_cron
```

## Где живут правила

| Правило | Где | Почему там |
|---|---|---|
| Переходы статусов и журнал | функции базы `create_order`, `transition_order`, `complete_order`, `reassign_order`, `change_order_priority` (миграция 0003) | Права, допустимость перехода, причина и запись в журнал — в одной транзакции. Обойти из интерфейса нельзя |
| Таблица переходов для кнопок | `apps/web/lib/orders/transitions.ts` | Интерфейс показывает только допустимые кнопки; проверка всё равно в базе |
| Кто что видит | правила доступа (RLS), миграции 0001–0002, 0006 | Исполнитель не видит и не меняет чужие наряды; служебные поля Telegram скрыты |
| Журнал неизменяем | триггер `work_order_events_immutable` | Записи нельзя изменить или удалить даже служебным ключом |
| Защита от дублей | `client_action_id` в каждом действии | Повтор из офлайн-очереди или при плохой связи не выполняется дважды |
| Просрочка | вычисляется (`lib/orders/transitions.ts: isOverdue`), не статус | Требование кейса |
| Контроль сроков | `lib/orders/deadlines.ts`, раз в минуту через `pg_cron` → `/api/cron/deadlines` | На бесплатном Vercel своё расписание — раз в сутки |
| ИИ-проверка закрытого наряда | `lib/ai/review.ts` | Код: полнота, материалы, время, повтор фото (`rules.ts`); модель: работы против проблемы и фото; вердикт сводит код (`decide`) |
| Рейтинг | `lib/analytics/rating.ts` | 5 составляющих кейса, веса в одном месте (`WEIGHTS`) |
| Аномалии | `lib/analytics/anomalies.ts` | 7 детекторов считает код; модель только пишет вывод и рекомендацию |

## ИИ-модули

| Модуль | Кто считает | Модель | Без модели |
|---|---|---|---|
| Контроль сроков | код | — | — |
| Полнота закрытия, материалы, время, повтор фото | код | — | — |
| Работы против проблемы | — | deepseek-flash | `needs_master` |
| Фото «до/после» | — | deepseek-flash (vision) | `needs_master` |
| Пояснение вердикта, сводка смены, тексты аномалий | цифры — код | deepseek-flash | шаблон из словаря |
| Шифр, приоритет, специальность по описанию | — | Laya (специальность, категория) + deepseek-flash (шифр, приоритет) | мастер выбирает сам |
| Подбор исполнителя | код | — | — |
| Чат-помощник мастера (`lib/ai/assistant.ts`) | факты смены, аномалии, рейтинг — код | deepseek-flash | ответ по ключевым словам из словаря |

Правила для всех вызовов (`lib/ai/provider.ts`): строгий JSON по схеме и проверка схемы, одна повторная попытка,
таймаут, источник ответа (`laya`, `llm`, `vlm`, `rules`) сохраняется. ФИО заменяются метками до отправки
(`lib/ai/anonymize.ts`), у фото метаданные удаляются при сжатии на телефоне (`lib/orders/photos.ts`).
Режим `cloud` / `local` переключается в настройках мастера (`settings.ai_provider`).

Результаты проверки Laya и дообучения — `docs/laya-eval.md`.

## Голос и язык интерфейса

- Голосовой ввод (`components/ui/VoiceButton.tsx`) — распознавание речи браузера (Web Speech API), без библиотек.
  Кнопка есть в описании наряда, в полях закрытия и в помощнике. Если браузер не умеет, кнопки нет.
- Диктофон мастера (`components/ui/Dictaphone.tsx`): запись → `app/api/voice` → Whisper large-v3-turbo на нашем Mac
  (`services/fast-ai`, `POST /transcribe`) → разбор по полям в `lib/ai/voice.ts`: Qwen3-4B через Ollama на Mac,
  иначе DeepSeek с обезличиванием, иначе текст без разбора. Машина и исполнитель сверяются со справочником кодом,
  поля показываются с пометкой «проверьте». Mac или сеть недоступны — распознавание телефона.
- Надписи — `messages/ru.json` и `messages/kk.json` с одинаковыми ключами (сборка падает, если ключа нет).
  Язык хранится в cookie `lang`, переключатель «Рус / Қаз» в шапке и на входе.
  Серверные компоненты берут перевод через `const t = await getT()` (`lib/i18n-server.ts`),
  клиентские — через `const t = useT()` (`components/LocaleProvider.tsx`).
- На русском остаются сообщения в Telegram, тексты для модели и запасные тексты ИИ, выгрузки Excel и PDF (`tRu`).

## Обновление в реальном времени

`lib/orders/RealtimeRefresh.tsx` подписывается на изменения `work_orders` в Supabase Realtime с токеном
вошедшего пользователя (правила доступа действуют и для событий) и просит Next перечитать данные страницы.
Замер: статус у мастера меняется меньше чем за 4 секунды.

## Каркас интерфейса v2

`components/shell/AppShell.tsx` кладётся один раз в layout каждой роли и в `app/(account)` (профиль и уведомления).
Одно дерево компонентов, две раскладки (`ShellFrame.tsx`): на телефоне белая шапка с плашкой связи и колокольчиком
и три кнопки внизу, на ПК тёмное меню слева с аккаунтом, связью и языком. Разделы ролей — `components/shell/nav.ts`.
Всплывающие сообщения — `components/ui/ToastProvider.tsx`, только четыре текста из `PLAN.md`, раздел 8.2.
Центр уведомлений читает `notifications` (миграция 0012: `read_at`, `notification_prefs`, тихие часы);
колокольчик обновляется через Realtime. `lib/notify` не шлёт в Telegram события, отключённые сотрудником,
и молчит в его тихие часы, но запись в центре уведомлений появляется всегда.

## Работа без сети

`lib/offline/queue.ts`: действие исполнителя без сети сохраняется в `localStorage` со своим `client_action_id`
и отправляется по порядку, когда сеть появится (`lib/offline/ConnectionProvider.tsx`). База отсеивает повторы.
Состояние очереди показывает плашка связи: «В сети», «Отправка · N», «Нет сети · N», «Ошибка · N»; по нажатию — список.
Service worker (`public/sw.js`): файлы приложения — из кэша, экраны — из сети с сохранением последней версии
(до 40 экранов). Без сети открывается сохранённый экран, а если его нет — страница «Нет сети». Запросы к `/api`,
Supabase и действия не кэшируются. Сохранённые экраны стираются при выходе из аккаунта.

## Android

`apps/android` — оболочка Trusted Web Activity (Bubblewrap) над тем же адресом, своей логики нет.
`app/.well-known/assetlinks.json` подтверждает ключ подписи (отпечаток в `ANDROID_SHA256_FINGERPRINTS`).
Сборка — `apps/android/README.md`.

## Данные

13 миграций в `supabase/migrations` (0011 — функции уровня 4: история ремонтов, «Нужна помощь», обработка попутных заявок; 0012 — центр уведомлений; 0013 — сводка по машине за 30 дней). Демо-история — `scripts/seed/generate.mjs` (592 наряда за 3 месяца,
4 заложенные закономерности, `docs/demo-data.md`). «Сбросить демо» восстанавливает снимок
(`restore_demo`, миграция 0009) и сдвигает даты к сегодняшнему дню.

## Безопасность

- Права — в базе, не в интерфейсе. Служебный ключ только на сервере (`lib/supabase/admin.ts`, `server-only`).
- Вход: логин → служебный адрес `<логин>@naryad.local`, пароль Supabase Auth (от 8 символов, буквы и цифры). Сброс пароля делает руководитель.
- Оператор без входа: заявку принимает `app/api/requests` и вызывает `submit_operator_request` служебным ключом (проверка QR, ФИО, не больше 5 заявок с телефона за 10 минут).
- Секреты расписания и вебхука Telegram сверяются в заголовках; секрет расписания хранится в Supabase Vault.
- Выгрузка отчётов доступна только мастеру и руководителю.
- Лицензии всех зависимостей проверены (`AI_TOOLS.md`).

## Интеграция с 1С / ERP / ТОиР

Всё состояние — в PostgreSQL с понятной схемой. Обмен строится через REST API Supabase
(служебный ключ на стороне интеграции) или выгрузки Excel. Справочники оборудования и материалов
можно загружать из ТОиР тем же способом, что и генератор (`scripts/seed`).
