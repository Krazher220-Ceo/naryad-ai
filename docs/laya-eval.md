# Laya на описаниях нарядов — результаты проверки

Обновлено: 7 октября 2026.

**Важно про данные.** Тестовый набор `services/fast-ai/eval_set.jsonl` и обучающие данные — **синтетические**:
обучающие 920 описаний сгенерировал `deepseek-flash`, тест (192 описания) написан вручную нами. Это не реальные заявки завода.
Метки (категория, приоритет, специальность) расставлены по единым правилам, но человеком-экспертом завода не проверялись.
Приоритет по своей природе спорный, поэтому цифры по нему — оценка, а не истина.

## Тестовый набор

192 описания: 171 на русском и 21 на казахском. Входят 20 описаний первого теста (3 октября) и 172 новых.
Распределение: категории М 66, Э 40, Г 31, П 27, С 28; приоритеты emergency 45, high 52, normal 50, planned 45;
специальности слесарь 131, электрик 40, сварщик 21. Правила разметки приоритета:
emergency — оборудование остановлено или опасно; high — работает, но быстро ухудшается; normal — мелкий дефект; planned — работы по графику.
Совпадений с обучающими данными нет (ни точных, ни по окну в 6 слов — проверено для текущего `train.jsonl`);
`make_data.py` теперь тоже убирает совпадения с `eval_set.jsonl`, если данные генерировать заново.
Ограничение: описания писал один автор в одном стиле, а обучающие — другая модель; на реальных заявках с опечатками и жаргоном цифры будут ниже.

## Результат (Mac, Laya 0.3.25, `finetune/eval_finetuned.py`)

| | Без дообучения | После дообучения |
|---|---|---|
| Категория шифра | 88/192 (46%) | 165/192 (86%) |
| Приоритет | 103/192 (54%) | 135/192 (70%) |
| Специальность | 83/192 (43%) | 173/192 (90%) |
| Только русский (171): категория / приоритет / специальность | 83 / 93 / 75 (49% / 54% / 44%) | 151 / 119 / 158 (88% / 70% / 92%) |
| Только казахский (21): категория / приоритет / специальность | 5 / 10 / 8 (24% / 48% / 38%) | 14 / 16 / 15 (67% / 76% / 71%) |
| Время на запрос | 62 мс | 63 мс |

Обе колонки — вопросы к Laya на английском (`questions.py`). Казахский в обучающих данных почти не представлен, поэтому на нём слабее (выборка 21, один случай — 5 п. п.).

**Матрица приоритета после дообучения** (строка — правильный ответ, столбец — ответ Laya):

| | emergency | high | normal | planned |
|---|---|---|---|---|
| emergency (45) | 42 | 1 | 1 | 1 |
| high (52) | 15 | 32 | 4 | 1 |
| normal (50) | 27 | 1 | 16 | 6 |
| planned (45) | 0 | 0 | 0 | 45 |

Laya уверенно отличает плановые работы (45 из 45), но завышает приоритет: 42 из 102 описаний с приоритетом high и normal
она называет emergency. Причина — обучающие данные учат «аварийность по словам» («остановлен», «дым», «греется»).
Это опасная ошибка для очереди: лишние аварии заглушают настоящие.

## Решение

- Из Laya берём **только категорию и специальность**. **Приоритет из Laya не используется**: `apps/web/lib/ai/classify.ts`
  берёт приоритет у языковой модели (DeepSeek или локальная); если доступна только Laya, приоритет остаётся пустым и его выбирает мастер.
- Категория 86% и специальность 90% — достаточно для подсказки, которую мастер видит и может поменять. Это не автоматическое решение.
- Laya не заменяет языковую модель: точный шифр из справочника она не выдаёт.
- Сервер `services/fast-ai` при перегрузке отвечает 503 `{"busy": true}`, приложение тогда идёт по запасному пути.

## Что не проверено

- Реальные заявки завода: проверки на них не было.
- Сравнение с DeepSeek на новом наборе не перезапускалось. На старых 20 описаниях DeepSeek давал 100% / 75% / 100%
  (категория / приоритет / специальность); для расширенного набора таких цифр нет.
- Разметка набора не проходила проверку независимым человеком.

## Дообучение на Mac (кратко)

Данные: 920 синтетических описаний (`finetune/make_data.py`, 48 запросов к `deepseek-flash`, метка — запрошенная комбинация).
Обучение: `finetune/train_mps.py`, fp32, батч 8 × накопление 4, 4 эпохи, AdamW, потеря RLCD + мягкая кросс-энтропия; 10% описаний отложено для калибровки температуры (1,075);
20 минут на MacBook Air M2 16 ГБ. Веса (`finetune/laya-naryad/`, 640 МБ) в репозиторий не входят; на других машинах их можно получить
из Hugging Face (`LAYA_MODEL=Krazher/laya-naryad`, пример id) или обучить заново (~25 минут).

**Как запустить** (из `services/fast-ai`):
- данные: `.venv/bin/python finetune/make_data.py`
- обучение: `.venv/bin/python finetune/train_mps.py 4`
- проверка: `.venv/bin/python finetune/eval_finetuned.py` (или `eval.py` для базовой модели)
- сервер: `FAST_AI_SECRET=... .venv/bin/uvicorn server:app --port 8787`
