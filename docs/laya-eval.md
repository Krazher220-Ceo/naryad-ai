# Laya на русских описаниях нарядов — результат теста

Дата: 3 октября 2026. Открытый вопрос из PLAN.md, раздел 11.

**Как проверяли.** 20 вымышленных описаний нарядов на русском (services/fast-ai/eval.py), для каждого
заранее записаны правильные категория шифра (М/Э/Г/П/С), приоритет и специальность.
Laya — чекпойнт `laya-multilingual` (пакет `laya` 0.3.25, без дообучения), MacBook Air M2.
Для сравнения те же 20 описаний классифицировала `deepseek-flash` с коротким описанием категорий.

| | Laya, вопросы по-русски | Laya, вопросы по-английски | DeepSeek |
|---|---|---|---|
| Категория шифра | 9/20 (45%) | 13/20 (65%) | 20/20 (100%) |
| Приоритет | 6/20 (30%) | 7/20 (35%) | 15/20 (75%) |
| Специальность | 5/20 (25%) | 11/20 (55%) | 20/20 (100%) |
| Время на запрос | 111 мс | 73 мс | ~2,2 с |

**Выводы.**
- Без дообучения Laya на нашем домене слабая, и бывает уверенно неправа
  («Искрит электрощит» → сварщик с вероятностью 0,96). Порог уверенности это не спасает.
- Приоритет спорный и для людей: даже DeepSeek расходится с разметкой в 5 случаях из 20.
- Авторы Laya пишут, что дообучение на своих решениях резко поднимает точность
  (0,362 → 0,766 на их тесте). Данные для дообучения у нас будут: генератор M3 даёт 500+ размеченных нарядов.

**Решение до дообучения.** Подсказку шифра, приоритета и специальности делает DeepSeek (источник `llm`).
Laya подключается к той же функции и становится основным путём после дообучения и повторного теста.

## Дообучение на Mac

Дата: 4 октября 2026. Цель: поднять точность Laya на русских описаниях нарядов, чтобы включить её как основной путь (`LAYA_ENABLED=1`).

**Данные.** 920 синтетических описаний (`services/fast-ai/finetune/make_data.py`). Их написал `deepseek-flash` по запросу
«заявка мастера с телефона» для каждой допустимой комбинации шифра, специальности и приоритета (6 пар × 4 приоритета, 48 запросов).
Метка описания — запрошенная комбинация. Это дистилляция из большой модели, а не реальные данные завода; качество меток не проверялось человеком.
Состав: категории М 300, Э 160, Г 140, П 160, С 160; приоритеты emergency 220, high 220, normal 240, planned 240;
специальности слесарь 620, сварщик 140, электрик 160 (электрик и сварщик реже, потому что их меньше в заводской жизни).
Тест — 20 описаний, написанных вручную (`eval.py`): в обучение и калибровку не попадали, из данных удалены совпадения с ними
(точные и по окну в 6 слов; нашлось 0).

**Обучение** (`finetune/train_mps.py`, адаптация скрипта авторов с Kaggle на одно устройство MPS):
fp32, градиентный чекпойнтинг, батч 8 × накопление 4 = 32, 4 эпохи, AdamW (энкодер 2,5e-5, голова 1e-4), косинусное расписание,
потеря RLCD + мягкая кросс-энтропия (цель 0,9 на верный вариант). Таблица слов заморожена (экономит память, обучалось 110M параметров энкодера и 15M головы).
По 3 вопроса (шифр, приоритет, специальность) на описание; 10% описаний (92) отложены для калибровки температуры,
отдельный вопрос о точности на них: 268/276 примеров верно (97%). Подобранная температура 1,075.
Время: 20 минут (1220 с) на MacBook Air M2 16 ГБ. Итоговая потеря на последней эпохе колеблется около нуля
(RL-часть отрицательна, поэтому судить стоит по `ce` ≈ 0,42, что близко к минимуму для сглаженных целей).

**Результат на 20 тестовых описаниях** (`finetune/eval_finetuned.py`):

| | Без дообучения | После дообучения | DeepSeek |
|---|---|---|---|
| Категория шифра | 13/20 (65%) | 17/20 (85%) | 20/20 (100%) |
| Приоритет | 7/20 (35%) | 9/20 (45%) | 15/20 (75%) |
| Специальность | 11/20 (55%) | 20/20 (100%) | 20/20 (100%) |
| Средняя уверенность (кат./прио./спец.) | 0,57 / 0,72 / 0,66 | 0,85 / 0,79 / 0,89 | |
| Время на запрос | 64 мс | 58 мс | ~2,2 с |

Самые уверенные ошибки после дообучения: «Обрыв кабеля питания…» приоритет emergency вместо high (0,89);
«Течь масла из-под уплотнения вала шламового насоса» категория М вместо Г (0,88);
«Пневмоцилиндр затвора бункера не двигается» emergency вместо high (0,88); «Не срабатывает датчик уровня» emergency вместо normal (0,87).

**Вывод.** Специальность стала 100%, категория 85% (порог ≥ 85% достигнут ровно на границе: 17 из 20, выборка мала).
Приоритет остался слабым (45%): метки приоритета в тесте спорные (даже DeepSeek даёт 75%), а синтетические данные учат «аварийность по словам»
(остановлен, дым → emergency), поэтому Laya часто завышает приоритет. Рекомендация: включать `LAYA_ENABLED=1` только для категории и специальности
(они ≥ 85%), а приоритет по-прежнему определять DeepSeek или оставлять выбор мастеру; при уверенности категории ниже 0,6 уходить в DeepSeek.
Перед включением стоит расширить тест до 50–100 описаний: на 20 один случай даёт 5 п. п.
Важно: `classify.ts` сейчас берёт приоритет из ответа Laya, так что при включении его нужно либо игнорировать, либо добирать у DeepSeek. Это решение за владельцем `lib/ai`.

**Как запустить** (из `services/fast-ai`, подробности в `README.md`):
- данные: `.venv/bin/python finetune/make_data.py`
- обучение: `.venv/bin/python finetune/train_mps.py 4`
- сравнение с тестом: `.venv/bin/python finetune/eval_finetuned.py`
- сервер: `FAST_AI_SECRET=... .venv/bin/uvicorn server:app --port 8787`

Веса (`finetune/laya-naryad/`, 640 МБ) и данные в репозиторий не входят (`.gitignore`); их можно получить заново за ~25 минут.
