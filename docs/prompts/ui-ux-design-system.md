# Промпт для Claude Code: UI/UX и дизайн-система «НарядAI»

Скопируй всё ниже в новую сессию Claude Code, открытую в корне репозитория.

---

Ты — ведущий UI/UX-дизайнер и фронтенд-разработчик проекта «НарядAI». Твоя задача: спроектировать интерфейс и собрать дизайн-систему, из которой другие агенты соберут экраны. Код ядра и экраны пишут другие. Ты делаешь основу, на которой всё будет выглядеть и работать одинаково хорошо.

## Сначала прочитай

1. `AGENTS.md`: правила обязательны. Особенно разделы «Интерфейс», «Правила кода», «Несколько агентов».
2. `PLAN.md`, разделы 1, 3, 6 и 8 (статусы наряда и веха M1).
3. Кейс: `Кейсы/1 кейс - Костанайские минералы/Кейс №1 Костанайские минералы рус.pdf`, разделы 3, 5, 6.4, 7, 11.
4. Текущий код: `apps/web/app/**`, `apps/web/components/AppHeader.tsx`, `apps/web/messages/ru.json`, `apps/web/lib/i18n.ts`.
5. Это Next.js 16. Перед кодом смотри `apps/web/node_modules/next/dist/docs/`.

## Кто пользователи и в каких условиях

- **Исполнитель** (слесарь, электрик, сварщик). Дешёвый Android, ширина 360 px, рабочие перчатки, грязные руки, яркое солнце или тёмный цех, шум, плохая связь. Читает на ходу, одной рукой. Ему нужно: увидеть новый наряд, понять, что и где сломано, нажать «Принять» → «Начать» → «Исполнено», заполнить закрытие, сделать фото.
- **Мастер смены.** Телефон и иногда ноутбук. Выдаёт наряд за минуту и не больше чем за 6 нажатий. Смотрит, кто свободен, что горит, что просрочено.
- **Руководитель.** Ноутбук. Смотрит дашборд, рейтинг, аномалии.
- **Жюри хакатона.** Открывает по ссылке без нас. Интерфейс должен быть понятен с первого взгляда.

## Что нужно сделать

### 1. Принципы и токены, файл `docs/ui/design-system.md`

Коротко и конкретно:
- палитра: фон, текст, основной цвет, акцент, ошибка;
- цвета статусов исполнителя: зелёный — свободен, жёлтый — в работе, синий — есть очередь, серый — не на смене;
- цвета приоритетов (аварийный — красный и всегда наверху) и цвета 11 статусов наряда;
- проверка контраста не ниже WCAG AA, в том числе на солнце: только насыщенные цвета, без бледно-серого текста;
- типографика: базовый размер не меньше 16 px, важное — 18–20 px;
- отступы, радиусы;
- размеры касания: основные кнопки не меньше 56 px, вторичные не меньше 48 px, промежутки между целями не меньше 8 px;
- правила: главное действие внизу экрана в зоне большого пальца; опасные действия (отклонить, отменить) отделены от основных и требуют подтверждения или причины;
- статус всегда показывается цветом **и** текстом (дальтонизм);
- пустые состояния и ошибки говорят, что делать дальше.

Токены оформи через Tailwind v4 (`@theme` в `apps/web/app/globals.css`), без новых библиотек.

### 2. Компоненты, папка `apps/web/components/ui/`

Только React, TypeScript и Tailwind. Никаких новых npm-зависимостей: ни shadcn, ни иконочных пакетов. Иконки — инлайн-SVG в `components/ui/icons.tsx`, только нужные.

Минимальный набор:
- `Button`: варианты primary, secondary, danger, ghost; размеры lg (56) и md (48); состояния loading и disabled; полная ширина.
- `BottomActionBar`: закреплённая панель главного действия с учётом `env(safe-area-inset-bottom)`.
- `Card`, `ListItem`.
- `StatusBadge`: статус наряда, 11 вариантов.
- `PriorityBadge`: 4 приоритета.
- `WorkerStatusDot` или `WorkerChip`: 4 цвета и подпись («свободен», «наряд №…», «в очереди N», «не на смене»).
- `OverdueTag`: просрочка — вычисляемый признак, не статус.
- `Field`, `TextInput`, `TextArea`, `Select`, `NumberStepper` (крупные + и − для количества материалов в перчатках).
- `SegmentedControl`: тип работ, приоритет — выбор одним нажатием вместо выпадающего списка.
- `ReasonPicker`: выбор причины из крупных готовых вариантов плюс «другое» с текстом. Нужен для отказа и паузы, причина обязательна.
- `PhotoPicker`: камера или галерея, до 5 фото, превью, удаление. Пока только UI, отдаёт `File[]` через `onChange`; загрузку подключат другие.
- `Stepper` / `StepForm`: форма по шагам на телефоне и одной страницей на ширине от `md`. Это **один** компонент с двумя раскладками, не два набора.
- `EmptyState`, `ErrorState`, `Skeleton`.
- `Toast` или `InlineNotice` для «Сохранено», «Нет сети, отправим позже».
- `ConfirmSheet`: нижний лист подтверждения вместо `window.confirm`.

Все надписи берутся из `apps/web/messages/ru.json` через `t()` из `apps/web/lib/i18n.ts`. Новые ключи добавляй в раздел `"ui"`, существующие не трогай. В компонентах не должно быть русского текста.

Типы статусов и приоритетов не придумывай. Значения в базе:
- статус наряда: `issued accepted queued rejected in_progress paused done ai_review rework closed cancelled`;
- приоритет: `emergency high normal planned`;
- тип работ: `planned unplanned`;
- роли: `master worker lead`.

Объяви их в `apps/web/components/ui/types.ts` как union-типы. Если позже появится `apps/web/lib/orders/types.ts`, переключись на импорт оттуда.

### 3. Спецификация экранов M1, файл `docs/ui/screens-m1.md`

Для каждого экрана опиши: цель, что видно сверху вниз, какие компоненты использованы, главное действие, пустое и ошибочное состояние, поведение на 360 px и на ноутбуке. Экраны:
1. Панель смены мастера: исполнители с цветными статусами, доска нарядов по статусам с просроченными и аварийными наверху, счётчики смены.
2. Выдача наряда. Распиши путь в **не больше 6 нажатий** с предзаполнением: что подставлено по умолчанию, какие нажатия делает мастер. Например: участок, оборудование, исполнитель, тип и приоритет одним касанием, срок по нормативу, фото — по желанию.
3. «Мои наряды» исполнителя: аварийный наряд красный и наверху, очередь, сроки.
4. Карточка наряда исполнителя: кнопки по статусу — принять, в очередь, отклонить, начать, приостановить, продолжить, исполнено.
5. Закрытие наряда по шагам: работы → шифр → материалы → фото «после» (обязательно для внеплановых) → комментарий → отправить.

Нарисуй для каждого экрана ASCII-набросок на 360 px.

### 4. Витрина: `apps/web/app/demo/ui/page.tsx`

Одна страница со всеми компонентами во всех состояниях, чтобы команда и другие агенты видели систему. Маршрут `/demo` уже открыт без входа.

## Ограничения

- Работай в отдельной ветке `feat/design-system`. Лучше в git worktree: `git worktree add .worktrees/design-system -b feat/design-system main`, затем `npm ci` и `cp` файла `.env.local` в `apps/web` этого worktree.
- **Не трогай:** `apps/web/lib/**` (кроме чтения), `apps/web/proxy.ts`, `supabase/**`, `apps/web/app/(master)`, `(worker)`, `(lead)`, `(auth)` — экраны пишут другие агенты параллельно. Ещё не трогай `package.json` и `package-lock.json`, `PLAN.md`, `AGENTS.md`.
- `apps/web/app/globals.css` меняй только добавлением `@theme` и базовых стилей. `AppHeader.tsx` можно перевести на новые токены, не меняя его props.
- Простой код, который школьник сможет пересказать. Без абстракций «на будущее».
- Не делай push в `main` и не сливай ветки. Делай коммиты в своей ветке, сообщения на русском в повелительном наклонении.
