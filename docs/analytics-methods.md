# Методы аналитики отказов

Кейс, п. 6.5: «ИИ-аналитика истории и поиск аномалий». Правило проекта: **считает код, модель понимает и объясняет.**
Все формулы ниже написаны на обычном TypeScript без библиотек и лежат в `apps/web/lib/analytics/`:
`stats.ts` (математика), `forecast.ts` (прогноз), `anomalies.ts` (детекторы). Модель получает готовые цифры
(в том числе p-значение и z) и только формулирует вывод.

## 1. Прогноз отказов на 7 дней (`forecast.ts`)

Данные: внеплановые наряды (не отменённые) за 90 дней, дата отказа — создание наряда.

**MTBF (среднее время между отказами) с подтяжкой к среднему по заводу.** Окно наблюдения `T` = 90 дней
разбивается отказами на интервалы, их сумма равна `T`. Чтобы 1–2 отказа не давали абсурдных значений:

    mtbf = (T + k · mtbf_завода) / (n + k),   k = 2

`n` — число отказов машины, `mtbf_завода = T · число_машин / все_отказы`. При `n = 0` результат близок к заводскому,
при большом `n` стремится к `T / n`.

**Вероятность отказа за 7 дней.** Экспоненциальная модель (отказы случайны, интенсивность постоянна):

    p7 = 1 − exp(−7 · f / mtbf)

`f` — поправка на рост (раздел 2), от 1 до 2.

**Рост отказов.** Для каждой машины сравниваем последние 30 дней с предыдущими 60. Ожидаемое число
за 30 дней `λ = (n_прошлых + 0,5) / 60 · 30`; наблюдали `k`. Вероятность увидеть не меньше `k` случайно — хвост Пуассона:

    P(X ≥ k) = 1 − Σ_{i=0}^{k−1} e^(−λ) · λ^i / i!

Рост признаётся, если `k ≥ 2` и `p < 0,05`. Тогда `f = (k + 0,5) / (λ + 0,5)`, но не больше 2
(долгая интенсивность уже частично включает рост, потолок защищает от двойного счёта).

**Тренд для графика.** Отказы по неделям (13 недель) и их сглаживание EWMA: `s_i = 0,3 · x_i + 0,7 · s_{i−1}`.

**Коды причин** (текст строится по словарю на экране): `trend_up`, `high_rate` (интенсивность вдвое выше заводской),
`recent_failure` (последний отказ не позже 2 дней назад), `little_data` (меньше трёх отказов).

## 2. Аномалии (`anomalies.ts`)

- **Проблемное оборудование:** в 2 и более раза чаще однотипного и `P(X ≥ k | среднее у однотипного) < 0,01` (Пуассон).
- **Рост отказов:** тот же тест, что в прогнозе (30 дней против 60). Для периода 30 дней не считается: нужно окно от 60 дней.
- **Возвраты на доработку у исполнителя и перерасход материалов:** модифицированный z-показатель
  по медиане и MAD, выброс при `z > 3,5`:

      z = 0,6745 · (x − медиана) / MAD,   MAD = медиана |x − медиана|

  Для исполнителей `x` — доля возвратов (исполнители с 10 и больше нарядами), для материалов — отношение списанного
  к норме среди списаний того же материала (плюс практический порог: не меньше 1,5 нормы). Если MAD равен нулю,
  масштаб берётся из среднего отклонения.
- Остальные детекторы (повтор шифра, поломки после ППР, ночная смена) остаются правилами с порогами: у них нет
  естественной непрерывной величины для статистического теста.

## 3. Почему так

- **Экспоненциальная модель и Пуассон** — стандарт для редких независимых событий; формулы короткие, их можно
  вывести на доске. Веибулл точнее для износа, но на 90 днях и 2–40 отказах параметр формы не оценить надёжно.
- **Медиана и MAD** вместо среднего и стандартного отклонения: сам выброс не портит оценку нормы.
- **Подтяжка к среднему** — простая байесовская идея: мало данных, значит доверяем общему уровню.

## 4. Ограничения

- Данные демонстрационные, сгенерированные скриптом; закономерности заложены заранее (`docs/demo-data.md`). Это проверка метода, не доказательство точности на реальном заводе.
- 90 дней истории: сезонность и износ не видны. Модель не знает про плановые ремонты и остановы, кроме уже случившихся отказов.
- На демо-данных у всех машин много отказов, поэтому вероятности по многим машинам высокие; важен порядок, а не абсолютное значение.
- Проверка на рост делается по каждой машине отдельно. При 25 машинах один-два ложных срабатывания при `p < 0,05` ожидаемы (проблема множественных проверок). Для боевого режима нужна поправка (Бонферрони или FDR).
- Прогноз не проверен на отложенной выборке (backtest). Это следующий шаг.
- Прогноз — рекомендация. Решение о ремонте принимает мастер.

## 5. Как подключить Isolation Forest позже

Кейс упоминает Isolation Forest. Схема подключения без смены интерфейса:

1. Признаки по машине и неделе: число отказов, доля ночных, простой, число повторов шифра, дней после планового ремонта.
2. Обучение и оценка — в `services/fast-ai` на Python (`scikit-learn`, лицензия BSD), отдельный маршрут `/anomaly-score`.
3. В `lib/analytics/forecast.ts` добавить поле `anomalyScore` и код причины `outlier_pattern`; формулы выше остаются как запасной путь, когда сервис недоступен (Mac → облако → правила).
4. Библиотеку записать в `AI_TOOLS.md`.
