# AGENTS.md — правила для ИИ-агентов

Этот файл читают все агенты, которые работают в репозитории: Antigravity, Claude Code и другие. Правила одни для всех.

## Проект

«НарядAI» — система нарядов на ремонт для промышленного предприятия, кейс №1 хакатона. Оператор сообщает о поломке по QR-коду, мастер выдаёт наряд с телефона или ПК, исполнитель принимает и закрывает его, ИИ проверяет выполнение и объясняет решение, руководитель видит аналитику.

Роли: оператор, исполнитель, мастер, руководитель. Человек без входа считается оператором.

Клиенты: веб-приложение (PWA) для ПК и телефона и Android-приложение. Наброски экранов — по ссылке в начале `PLAN.md`, раздел 8.

До начала работы прочитай `PLAN.md`: объём по уровням, архитектура, таблицы, статусы. Текст кейса лежит в `Кейсы/`. Если `PLAN.md` расходится с кейсом, прав кейс: скажи об этом человеку.

Срок сдачи — 8 октября. Код замораживается в 14:00 8 октября.

## Приоритеты

Когда цели конфликтуют, выбирай в таком порядке:

1. **Работает.** Сценарий из раздела 11 кейса проходит от начала до конца. Жюри проверяет приложение по ссылке без нас, поэтому сломанный главный сценарий стоит дороже любой недостающей функции.
2. **Соответствует кейсу.** Сначала уровень 1 целиком, потом уровень 2, потом 3, потом 4. Не начинай следующий уровень, пока не готов предыдущий.
3. **Понятно.** По правилам хакатона команда обязана объяснить любой фрагмент кода. Пиши простой код, который школьник сможет пересказать.
4. **Удобно.** Интерфейс рассчитан на рабочего в перчатках.

## Как работать

- Перед задачей больше чем на один файл коротко опиши план и дождись подтверждения.
- Делай задачу в рамках объёма из `PLAN.md`. Не добавляй функции, которых нет в плане. Если видишь полезное улучшение, предложи его, но не делай.
- Меняй только то, что нужно для задачи. Не переформатируй и не переименовывай чужой код заодно.
- Сначала самый простой рабочий вариант, потом улучшения.
- После задачи напиши: что сделано, как проверить, что осталось. Если что-то не проверено, скажи прямо.
- Если не уверен в требовании, спроси. Не угадывай.

## Несколько агентов и людей в одном репозитории

В репозитории одновременно работают два агента и два человека.

- Перед началом выполни `git status` и `git pull`. Не начинай на грязном рабочем дереве с чужими изменениями.
- Одна задача — одна ветка: `feat/<коротко>`, `fix/<коротко>`. В `main` напрямую не пиши.
- Не трогай файлы, над которыми в этот момент работает другой агент или человек. Если нужно изменить общий файл, сначала скажи об этом.
- Коммиты маленькие, сообщение на русском в повелительном наклонении: «Добавить форму закрытия наряда».
- Миграции базы только новыми файлами с следующим номером. Уже применённые миграции не редактируй.
- Зоны ответственности: ядро и `lib/orders`, `lib/requests`, `lib/ai`, `lib/offline`, `supabase/migrations`, `services/fast-ai`, `apps/android` — Алихан. `scripts/seed`, `lib/notify`, центр уведомлений, отчёты и дашборд — Бауыржан. Вне своей зоны меняй код только с согласия владельца.

## Стек

- Клиент: Next.js (App Router), React, TypeScript, Tailwind, PWA
- Android: оболочка TWA над тем же веб-приложением (`apps/android`). Правила для Android — в разделе «Android-приложение»
- База: Supabase (PostgreSQL, Auth, Storage, Realtime)
- Быстрый ИИ: Python, FastAPI, Laya в `services/fast-ai`
- Голос и локальная языковая модель: Whisper large-v3-turbo и Qwen3-4B на нашем Mac, в `services/fast-ai`
- Уведомления: Telegram Bot API

Не добавляй новые библиотеки и сервисы без согласования. Каждую добавленную зависимость запиши в `AI_TOOLS.md`.

## Команды

Все команды приложения выполняются в папке `apps/web`. Перед каждым коммитом запускай проверку типов и линтер.

```
установка:        cd apps/web && npm install && cp ../../.env.example .env.local   (заполнить ключи)
запуск:           cd apps/web && npm run dev            (http://localhost:3000)
проверка типов:   cd apps/web && npm run typecheck
линтер:           cd apps/web && npm run lint
сборка:           cd apps/web && npm run build
тесты:            supabase/tests/order_cycle.sql — цикл наряда на настоящей базе
                  (SQL Editor или execute_sql через MCP; всё откатывается)
миграции:         новые файлы supabase/migrations/NNNN_*.sql; применяются к проекту Supabase
                  через Supabase MCP (apply_migration) или `npx supabase db push`
android:          apps/android — сборка APK через Bubblewrap (инструкция в apps/android/README.md, появится в M8)
qr для проверки:  node scripts/qr/make-test-qr.mjs [адрес-приложения]
генерация данных: минимальные справочники и демо-логины — supabase/seed.sql
                  (выполнить в SQL Editor Supabase); полный генератор — scripts/seed (M3)
```

Next.js в проекте версии 16: `middleware.ts` переименован в `proxy.ts`. Перед кодом читай документацию в `apps/web/node_modules/next/dist/docs/`.

## Правила кода

- TypeScript в строгом режиме. Не используй `any` без причины.
- Имена в коде на английском. Комментарии короткие, на русском, только там, где код неочевиден.
- Все надписи интерфейса берутся из словарей `messages/ru.json` и `messages/kk.json`. Новая надпись добавляется в оба файла. Не пиши текст прямо в компонентах. На сервере перевод — `await getT()`, в браузере — `useT()`. Сообщения в Telegram, тексты для модели и выгрузки — на русском через `tRu`.
- Секреты только в `.env`. В репозитории лежит `.env.example` без значений.
- Проект запускается одной командой из README.

## Бизнес-правила, которые нельзя нарушать

- **Статусы и переходы** описаны в разделе 6 `PLAN.md`. Код переходов живёт в одном месте, `lib/orders`. Не меняй статус наряда в обход него.
- **Каждое изменение статуса создаёт запись** в `work_order_events` в той же транзакции. Записи журнала не изменяются и не удаляются.
- **Отклонение и пауза требуют причину.**
- **Просрочка — вычисляемый признак**, а не статус.
- **Финальное решение за мастером.** ИИ рекомендует, наряд закрывает человек. Изменение оценки мастером сохраняется вместе с причиной.
- **Права проверяются на сервере**, через правила доступа Supabase, а не скрытием кнопок. Исполнитель не может изменить чужой наряд.
- **Вход по логину и паролю.** Пароль не короче 8 символов, буквы и цифры. Сбрасывает пароль руководитель.
- **Оператор без входа обязательно указывает ФИО.** Его заявка идёт только через серверный маршрут с проверкой QR и ограничением частоты, не прямой записью в таблицу. Наряд из заявки выдаёт мастер.
- **Фото «после» обязательно** для внеплановых работ.

## Правила для ИИ-модулей

- Считает код, модель понимает и объясняет. Статистику, рейтинг и поиск аномалий выполняет код. Модель получает готовые цифры и формулирует вывод. Не отправляй в модель сырые строки с просьбой «найди закономерность».
- Все вызовы моделей идут через `lib/ai`. Не обращайся к провайдеру напрямую из компонентов и маршрутов.
- Ответ модели всегда в строгом JSON по схеме. Проверяй схему. При ошибке разбора повтори запрос один раз, затем верни `needs_master`.
- При низкой уверенности вердикт — `needs_master`. Не выдумывай оценку.
- Проверка фото отделяет то, что видно, от того, что проверить нельзя (поле `cannot_verify`).
- У каждого вызова есть таймаут и запасной путь. Недоступность Laya, нашего Mac или облачного провайдера не должна останавливать цикл наряда: Mac → облако → правила и `needs_master`.
- Голос: Whisper даёт текст, модель возвращает поля в строгом JSON, человек проверяет поля перед заполнением формы. Без сети — распознавание браузера, текст без разбора.
- Используем только модели и библиотеки с лицензиями MIT, Apache 2.0 или BSD. Модели с ограничивающими лицензиями (Gemma, Llama, Qwen2.5-3B и подобные) не берём. Лицензию записываем в `AI_TOOLS.md`.
- В ответе сохраняется источник: `laya`, `llm`, `vlm`, `rules`.

## Данные и безопасность

- Персональные данные сотрудников и операторов не уходят во внешние сервисы. В облачном режиме `lib/ai` заменяет ФИО на номера до отправки и подставляет обратно после ответа. Не обходи этот слой.
- Перед отправкой фото наружу удаляй метаданные.
- Все справочники и история нарядов — демонстрационные, сгенерированные. Не выдавай их за реальные данные завода ни в коде, ни в текстах интерфейса.
- Если партнёр передаст реальные данные, они лежат в `data/`, которая исключена из репозитория.

## Интерфейс

- Сначала телефон. Проверяй экран на ширине 360 пикселей.
- Кнопки высотой от 56 пикселей, главное действие внизу экрана.
- На телефоне формы идут по одному шагу, на компьютере — одной страницей. Это одна форма в двух раскладках, не два набора компонентов.
- Цвета статусов исполнителя: зелёный — свободен, жёлтый — в работе, синий — есть очередь, серый — не на смене. Аварийное — красное и наверху.
- Фирменный стиль НарядAI: цвета берутся только из токенов `app/globals.css`, заголовки — Oswald, текст — Inter. Описание — `docs/ui/design-system.md`.
- Телефон: внизу три кнопки, средняя крупная. На экранах одного наряда нижнего меню нет. ПК: тёмное меню слева, аккаунт внизу.
- Плашка связи — на телефоне сверху справа, на ПК слева внизу у аккаунта. Всплывающие сообщения — только тексты из `PLAN.md`, раздел 8.2.
- Выдача наряда — не более 6 нажатий. Используй предзаполнение.
- Пустые и ошибочные состояния показывают, что делать дальше.

## Android-приложение

- Android-приложение — это клиент того же веб-приложения. Основной путь — оболочка TWA в `apps/android`: тот же адрес, тот же код, та же база.
- Нативный клиент (например, собранный в Google AI Studio) допускается только как тонкий клиент: вход через Supabase Auth, данные только через те же функции базы, правила доступа и серверные маршруты. Своей логики переходов статусов, прав, проверок и подсчётов в нём нет.
- Код Android-клиента лежит в репозитории в `apps/android`, команда должна уметь его объяснить (п. 6.4 положения).
- Синхронизация не делается отдельно: все клиенты работают с одной базой и получают изменения через Realtime.
- Ключ подписи APK и прочие секреты не коммитятся.
- Модели ИИ на телефоне не запускаются: распознавание, проверка и разбор идут на сервере.

## Чего не делать

- Не пиши бизнес-логику в Android-клиенте и не запускай модели на телефоне.
- Не удаляй и не переписывай тестовые данные без запроса. Для сброса есть «Сбросить демо».
- Не коммить секреты, содержимое `data/` и большие файлы весов.
- Не отключай проверки типов, линтер и правила доступа, чтобы «заработало».
- Не помечай задачу готовой, если она не проверена. Напиши, что именно не проверено.

## Готово — это когда

- Задача работает на телефоне, а не только на компьютере
- Проверка типов и линтер проходят
- Сценарий из раздела 11 кейса по-прежнему проходит
- Новые надписи добавлены в оба словаря: `ru.json` и `kk.json`
- Если изменение затрагивает телефон — проверено и в Android-приложении
- Новые зависимости записаны в `AI_TOOLS.md`
- README и `docs/architecture.md` обновлены, если изменилась схема запуска или архитектура
