# PLAN.md — «НарядAI»

Кейс №1 хакатона Qostanai AI Industry Hackathon 2026, заказчик — АО «Костанайские минералы».
Полный текст кейса: `Кейсы/1 кейс - Костанайские минералы/Кейс №1 Костанайские минералы рус.pdf`. При любом сомнении прав кейс, а не этот файл.

## 1. Что строим

Система нарядов на ремонт. Мастер выдаёт наряд с телефона, исполнитель принимает и закрывает его, ИИ следит за сроками, проверяет выполнение по тексту и фото, считает рейтинг и ищет закономерности в истории.

Наше отличие — двухслойный ИИ-контролёр:

- **Быстрый слой (Laya).** Открытая модель решений на нашем сервере. По тексту определяет шифр, приоритет и нужную специальность, возвращает вероятность.
- **Медленный слой.** Мультимодальная модель сравнивает фото «до» и «после», языковая модель объясняет результат человеку.
- **Вердикт с доказательствами.** ИИ отдельно пишет, что видно, что сошлось и что проверить нельзя. Финальное решение всегда за мастером.

## 3. Объём

### Уровень 1 — обязательно (раздел 10 кейса)

- Выдача наряда мастером с телефона со всеми полями и фото, за 1 минуту и не более 6 нажатий
- Статусы исполнителей в реальном времени, обновление не дольше 5 секунд
- Экран исполнителя: все кнопки статусов, фото, комментарии, шифры, материалы
- Уведомления на телефон
- Контроль просрочек с сообщениями исполнителю и мастеру
- Проверка закрытого наряда и отчёт с оценкой исполнителю и мастеру
- Отчёт за смену
- Рейтинг исполнителей
- Тестовые данные: 4 участка, 25 единиц оборудования, 2 мастера, 15 исполнителей в 3 бригадах, 20 шифров, 40 материалов, 500+ нарядов за 3 месяца, 3–4 заложенные закономерности

### Уровень 2 — желательно

- Сравнение фото «до/после» мультимодальной моделью
- Отчёты по материалам и простоям
- Поиск аномалий и зависимостей с текстовыми выводами
- Подбор исполнителя
- Дашборд руководителя
- Работа без сети: действия сохраняются на телефоне и отправляются при появлении связи
- Выгрузка в PDF и Excel

### Уровень 3 — бонус кейса

- Голосовой ввод наряда и закрытия
- Подсказка шифра и норматива по описанию
- Чат-помощник мастера
- Ранний сигнал об отказе (рост числа внеплановых нарядов)
- QR-код на оборудовании
- Казахский язык интерфейса

### Уровень 4 — наши дополнения (в кейсе их нет)

- Защита от дублей: предупреждение, если по оборудованию уже есть открытый наряд
- Учёт допусков при подборе исполнителя
- Баланс нагрузки между исполнителями
- Шаблоны плановых работ
- «Что взять с собой» по шифру
- «Как чинили в прошлый раз»
- Проверка безопасности перед началом работ
- Кнопка «Нужна помощь»
- Попутная находка: заявка мастеру из открытого наряда
- Силуэт фото «до» в камере при съёмке «после»

### Нужно для проверки жюри

Жюри проверяет решение по ссылке, без нас. Делается в M4, сокращению не подлежит.

- Стартовая страница с тестовыми логинами и шагами сценария из раздела 11 кейса
- Кнопка «Сбросить демо»: база возвращается в исходное состояние
- Демо-сроки: наряд можно выдать со сроком в 2 минуты, пороги напоминаний настраиваются

### Не делаем

- Отдельное нативное приложение под Android (APK при необходимости собирается оболочкой над PWA)
- Модель ИИ на самом телефоне

Остальные идеи — в плане развития на странице проекта, они идут на слайд.

## 4. Архитектура

```
apps/web  (Next.js, PWA)            один код для мастера, исполнителя, руководителя
   |
   |-- Supabase                     PostgreSQL, вход, хранилище фото, Realtime
   |-- /api/* (серверные маршруты)  проверка наряда, сроки, аналитика, отчёты
   |-- services/fast-ai (FastAPI)   Laya на нашем сервере
   |-- провайдер ИИ                 облако с обезличиванием | локальная модель
   |-- Telegram Bot API             уведомления
```

| Слой | Технология |
|---|---|
| Клиент | Next.js (App Router), React, TypeScript, Tailwind, PWA |
| База и вход | Supabase: PostgreSQL, Auth, Storage, Realtime |
| Быстрый ИИ | Python, FastAPI, Laya (открытые веса) |
| Медленный ИИ | Мультимодальная и языковая модель через слой `lib/ai` |
| Уведомления | Telegram-бот |
| Хостинг | Vercel для приложения, свой сервер для `services/fast-ai` |

Ключевые решения:

- **Источник ИИ переключается** переменной `AI_PROVIDER=cloud|local`. В облачном режиме ФИО заменяются на номера до отправки и подставляются обратно после ответа.
- **Laya не должна ронять приложение.** Вызов с таймаутом 1,5 секунды. Если сервис недоступен, ту же задачу выполняет языковая модель, в ответе помечается источник.
- **Контроль сроков работает по расписанию раз в минуту.** Расписание запускается из Supabase (`pg_cron`) и вызывает `/api/cron/deadlines` с секретом. На бесплатном тарифе Vercel собственное расписание срабатывает не чаще раза в день, поэтому на него не рассчитываем.
- **Вход по логину и ПИН-коду** через Supabase Auth: логин превращается в служебный адрес, ПИН из 6 цифр служит паролем.
- **Все надписи интерфейса берутся из словаря** с первого дня (`messages/ru.json`), чтобы казахский добавлялся файлом `kk.json`.
- **Каждое действие исполнителя имеет свой идентификатор** (`client_action_id`). Повторная отправка из офлайн-очереди не создаёт дубль.

### Статусы наряда

Десять статусов из кейса плюс отмена, которую кейс требует в пункте 5.1.

| Код | Название |
|---|---|
| `issued` | Выдан |
| `accepted` | Принят в работу |
| `queued` | В очереди |
| `rejected` | Отклонён |
| `in_progress` | В работе |
| `paused` | Приостановлен |
| `done` | Исполнено |
| `ai_review` | Проверка ИИ |
| `rework` | На доработку |
| `closed` | Закрыт |
| `cancelled` | Отменён мастером |

Допустимые переходы:

```
issued      -> accepted | queued | rejected
queued      -> accepted
accepted    -> in_progress
in_progress -> paused | done
paused      -> in_progress
done        -> ai_review          (автоматически)
ai_review   -> closed | rework    (решает мастер, ИИ рекомендует)
rework      -> in_progress
rejected    -> issued             (мастер переназначил)
любой до closed -> cancelled      (только мастер)
```

Просрочка — это не статус, а вычисляемый признак: `due_at < now()` и статус раньше `done`.
Отклонение и пауза требуют причину. Время паузы с причинами «ждёт запчасть», «ждёт допуск», «ждёт остановки оборудования» в просрочку исполнителю не засчитывается.

## 7. ИИ-модули

Правило: всё, что можно посчитать, считает код. Модель используется, чтобы понять текст или фото и чтобы объяснить результат словами.

| Модуль | Вход | Выход | Чем |
|---|---|---|---|
| Контроль сроков | открытые наряды | уведомления, эскалация | код по расписанию |
| Полнота закрытия | наряд | список незаполненного | код |
| Соответствие работ проблеме | описание проблемы, описание работ | да/нет, пояснение | языковая модель |
| Логичность материалов | списания, шифр, `typical_qty` | замечания | код |
| Повтор фото | новое фото, прошлые фото | совпадение и похожесть | код: sha256, перцептивный хеш |
| Фото «до/после» | два фото, оборудование, описание | JSON ниже | мультимодальная модель |
| Шифр, приоритет, специальность | описание проблемы | класс и вероятность | Laya, запасной вариант — языковая модель |
| Подбор исполнителя | специальность, смена, очередь, допуски, рейтинг | список кандидатов с пояснением | код |
| Рейтинг | история нарядов | балл и его составляющие | код, пояснение от модели |
| Аномалии | история нарядов | карточки с цифрами | код, текст от модели |
| Сводка за смену | цифры смены | короткий текст | языковая модель |
| Голос | аудио | текст | распознавание в браузере, локально Whisper |

Формат ответа проверки фото:

```json
{
  "same_equipment": {"value": true, "confidence": 0.92, "evidence": "..."},
  "visible_problem_before": "...",
  "visible_problem_after": "...",
  "repair_visible": true,
  "quality_findings": ["..."],
  "cannot_verify": ["..."],
  "score": 4,
  "confidence": 0.78,
  "verdict": "accept | accept_with_note | rework | needs_master"
}
```

Если уверенность ниже порога, вердикт — `needs_master`. ИИ не выдумывает оценку.

Рейтинг включает все пять составляющих из кейса: средняя оценка качества, доля нарядов в срок, доля возвратов и повторных поломок за 7 дней, количество и сложность, отказы без уважительной причины. Веса задаёт Али. При числе нарядов меньше 5 показывается пометка «мало данных».

## 8. Вехи и критерии готовности

### M0 — основа (3 октября)

- Репозиторий, Next.js, Supabase, первая миграция со всеми таблицами
- Вход по логину и ПИН-коду, три роли видят разные экраны
- Справочники загружены (минимальный набор)
- Приложение открывается по ссылке с телефона

### M1 — цикл наряда (4 октября, контрольная точка)

Проверка на двух телефонах Android:

1. Мастер видит список исполнителей с цветными статусами
2. Мастер создаёт наряд со всеми полями и фото
3. У исполнителя наряд появляется без обновления страницы
4. Исполнитель проходит: принять → начать → приостановить с причиной → продолжить → исполнено
5. Форма закрытия по шагам: работы, шифр, материалы, фото «после», комментарий
6. Статус у мастера меняется не дольше чем за 5 секунд
7. Каждый переход записан в `work_order_events`
8. Работают отказ с причиной, очередь, переназначение, отмена

### M2 — контроль и проверка (5 октября)

- Напоминание за 30 минут, сообщение о просрочке исполнителю и мастеру, эскалация при непринятом наряде (10 минут, аварийный — 3)
- Привязка Telegram и отправка всех типов сообщений
- Проверка закрытого наряда: полнота, соответствие, материалы, время → вердикт и отчёт
- Мастер соглашается с оценкой или меняет её, изменение сохраняется с причиной
- Наряд без фото и с лишними материалами получает «требует доработки» с объяснением

### M3 — уровень 1 готов (6 октября)

- Генератор создаёт 500+ нарядов с закономерностями, запускается повторно с тем же результатом
- Рейтинг исполнителей с разбивкой по составляющим
- Отчёт за смену с текстовой сводкой
- Проверка фото «до/после» и поиск повторного фото
- Laya подключена, есть запасной путь, источник ответа виден
- Подбор исполнителя с пояснением
- QR-коды оборудования и страница для печати

### M4 — уровень 2 готов (7 октября)

- Карточки аномалий находят все заложенные закономерности
- Отчёты по материалам и простоям, дашборд руководителя
- Выгрузка в PDF и Excel
- Офлайн-очередь: действие в режиме полёта доходит после появления сети, без дублей
- Стартовая страница для жюри, «Сбросить демо», демо-сроки
- README с инструкцией запуска, `docs/architecture.md`, `AI_TOOLS.md`
- Видео демо до 3 минут и презентация до 10 слайдов

### M5 — бонусы и дополнения (8 октября, до 14:00)

Сначала уровень 3, потом уровень 4. Каждый пункт сливается в основную ветку, только если он работает и ничего не ломает.
